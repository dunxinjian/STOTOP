## 2. 金额双列模型（关键：规避单列带符号金额坑）

韵达 `交易金额` 是单列带符号（`公司扣款/提款凭证`=正=网点被扣=成本/支出；`公司退款/充值凭证`=负=网点收到=收入/入金；`期初−交易=期末` 已验证）。

引擎（`AutoVoucherHandler`）对单列带符号金额**不翻方向、不取绝对值**，且 `createDraft` 的 `BuildDraftRequest` 硬编码累加 `F发生额收入/F发生额支出`。故导入规则 3150 用 `transformRules` 从 `交易金额` 派生两非负列：

```
F发生额支出 = (parseFloat(row['F交易金额'])||0) > 0 ? 该值 : 0
F发生额收入 = (parseFloat(row['F交易金额'])||0) < 0 ? -该值 : 0
```

凭证规则 3151 的收入行取 `F发生额收入`、成本行取 `F发生额支出`，方向固定（对齐申通双列模型）。派生列成为 DataTable 列的手法：`columnMapping` 把 `交易金额` 同时映到 `F交易金额/F发生额收入/F发生额支出`，`transformRules` 再覆盖后两者（同极兔 map-then-overwrite）。

经营单元：`F公司编码` → 核心名（`992209→城区`、`744706→浏河`）写入 `F归属网点编号`，凭证 `business_unit` 用 `matchBy:contains`。回归见 `tests/.../Import/YundaHqTxTransformTests.cs`。

- 匹配键 `matchingLayers.exactMatchField = F三级科目编码`（如 `308-1`），每码一组 2 行镜像分录。
- **对手腿统一 `220201 总部应付`(FID 700125) + `express_brand=YD` 辅助核算**（与申通/极兔一致；覆盖 06-15 文档的 1012 方案）。损益业务行四维辅助：`outlet`(F公司编码 动态)/`express_brand=YD`(固定)/`business_direction`(IN 派件·OUT 揽件·CMB 其余 固定)/`business_unit`(F归属网点编号 动态含)。

## 5. 辅助核算解析现状（已核）

四维辅助核算，接线后可解析情况（`AutoVoucherAuxiliaryResolver`）：
- `express_brand=YD`：fixed 按 code，YD 已在 `EXP品牌` → aux 运行时同步，**解析 ✓**。
- `business_direction`(IN/OUT/CMB)：fixed 按值，`BasicDataSeeder` 已 seed，**解析 ✓**。
- **`business_unit`(经营单元)：解析 ✓（非缺口）**。导入派生 `F归属网点编号=城区/浏河`，规则用 `matchBy:contains`（`a.Name.Contains(值)`），命中 `BasicDataSeeder` 已 seed 的 `BU-CQ 城区公司`/`BU-LH 浏河公司`（同极兔 V64 口径）。**阿米巴按经营单元上卷的维度天然可用，无需登记。**
- `outlet`(992209/744706)：`org_scoped`，由 `EXP快递网点` 同步而非 seed。**唯一可能落空的维度**——但与 business_unit 冗余（都标识网点），且缺失时引擎只 log warning、非致命（graceful degrade）。**非阻塞**。
