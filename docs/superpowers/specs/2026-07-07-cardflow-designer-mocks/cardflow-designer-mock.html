CardFlow 卡片流程设计器 · 交互设计方案

参考钉钉「四步向导」与企业微信「表单+流程分区」的成熟范式，结合 CardFlow 独有的自动节点、字段脱敏、路径干跑等能力重新设计。核心取舍：用结构化竖向流程图（受限编辑）替代自由画布作为编辑入口，让「图永远合法」，把一整类发布门禁错误消灭在交互层。

四步向导可自由往返竖向节点 + "+"插入条件分支横向展开 + 强制兜底 字段权限矩阵路径干跑预览草稿自动保存 · 发布门禁诊断直达现场
发起/结束 审批人（人工） 自动处理（导入/质检/凭证/通知） 抄送人 命中/激活态

超越钉钉/企微的设计点 ①：跨步骤联动锁定

  • 企微要求"条件字段必须必填且限类型"，但只在流程设计时才报错。这里反向锁定：字段一旦被某条分支用作路由条件，回到卡片设计步骤时自动挂 🔗 路由依赖 标记。

设计说明 · 为什么放弃自由画布作为编辑入口

  • 受限编辑，图永远合法：只能在"+"处插入合法节点，用户无法造出孤儿节点、非法边、断头路——一整类发布门禁错误在交互层面被消灭。
  • 四类可插入节点：审批人 / 抄送人 / 条件分支 / 自动处理（导入·质检·凭证·通知，紫色虚线框与人工节点区分）——最后一类是 CardFlow 独有。
  • 退回/跳转不画边：引擎语义是"审批人运行时现场选目标节点"（已核实为伪需求，无需设计期连线），竖向图用虚线标注即可。
  • 自由画布降级为"只读总览图"（顶栏 segmented 第二项）：节点多时看全局或看运行态分布，不承担编辑职责。

超越钉钉/企微的设计点 ②：强制兜底分支

  • 末列固定"其他情况"，不可删除：从交互上根治"规则不覆盖导致运行时无路可走"——比钉钉/企微仅靠优先级更稳。
  • 优先级可拖拽调序：从左到右命中即走，不再判断后面分支。
  • 条件构建器：组内"且"、组间"或"；可选字段限定为可判定类型（数字/金额/单选/组织/人员），且必须在卡片设计中设为必填（联动锁定见屏 2）。
  • 分支下仍可继续插入：每条分支是独立子流程，可再加审批/自动节点甚至嵌套分支。

  • 五区分 Tab：基础（名称/人工 vs 自动）、处理人（类型/或签会签/加签转交）、字段权限（逐字段可编辑/只读/隐藏）、动作（自定义按钮/失败策略）、高级（超时/去重）。

超越钉钉/企微的设计点 ③：脱敏字段总览校验

  • 敏感字段整行高亮（🔒 银行卡号）：一眼看出它在"抄送归档"节点仍是只读而非隐藏（红框告警），漏配脱敏在矩阵视图暴露无遗。
  • 对有脱敏语义的 CardFlow 必要——钉钉只能逐节点点进去配字段权限，无法横向审计。
  • 矩阵与节点抽屉的"字段权限"Tab 双向同步，改任一处另一处即时反映。

超越钉钉/企微的设计点 ④：路径干跑（CardFlow 后端能力已具备）

  • 高亮实际路径：绿色链路 = 这组样例值会真实走过的节点；灰色 = 未命中。分支判定结果就地标注。
  • 实时解析"派给谁"：人工节点角标显示按处理人策略解析出的真实人名（如"部门主管→李强"），发布前即可验证策略配错。
  • 三视角 × 双设备：处理人/观察者/发起人 × PC/移动，复用运行时呈现管线（脱敏、聚合真实生效），杜绝设计期预览与运行时漂移。
  • 含自动节点、字段脱敏的 CardFlow 价值极高——这是钉钉/企微完全没有的能力。

诊断面板 · 每条直达现场

点顶栏"问题"徽标滑出诊断列表，每条可点击直达出错的节点/分支/字段，而非发布时一次性弹一堆文案。

敏感字段「银行卡号」在"抄送归档"节点未设为隐藏 — 存在脱敏泄漏风险
定位到矩阵单元格 →

设计说明

  • 常驻计数徽标：顶栏"问题 3"实时更新，编辑期即可发现，不必等到点发布。
  • 定位式修复：每条诊断携带 target{kind:node|edge|field, key}，点击切到对应步骤 + 高亮节点/分支/矩阵单元格并展开编辑器——而非只弹一句文案让用户自己找。
  • 发布门禁前后端镜像：前端诊断规则与后端 CardComponentPublishValidator 同源，避免"前端过、后端拒"。
