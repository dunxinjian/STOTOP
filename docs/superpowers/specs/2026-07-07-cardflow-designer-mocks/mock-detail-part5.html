E1

退回 × 重提 × 路由条件变化（补 D-1）

单一真源：重提走向只在发起节点配置。核心新规则：重提修改了路由条件字段 → 强制重走分支判定。

场景时间线：中额单被退回后改成大额
发起
张伟提交 ¥8,000 → 命中「中额」分支 → 财务经理李强审批
退回
李强退回发起人：「发票金额与明细不符，请更正」
重提·改值
张伟更正为 ¥12,000（触碰路由条件字段「报销金额」，且跨档 中额→大额）
系统裁决
忽略「回到退回节点」配置，强制重走分支判定 → 命中「大额」→ 财务总监会签。时间线插入系统事件：因条件字段变化重新路由：金额 8,000→12,000（中额→大额）
对照
若重提只改了「报销事由」（非路由字段）→ 按配置「回到退回节点」直接回李强，不重走
规则矩阵（重提走向裁决）
配置未改路由字段改了路由字段
回到退回节点回退回节点强制重走分支判定
重走全程重走全程重走全程
条件 diff 渲染（并入 P-2 · 用于发布变更清单）
改大额：金额 ≥ 5000 → 10000
增大额：+ 且 费用类型 属于 [差旅]
值级 diff 内联渲染（旧删除线→新加粗），不展结构树。

设计裁决

  • 业务正确性 > 用户配置：跨档不重审是真实资损漏洞，系统裁决优先，且在时间线留系统事件保审计。
  • 判定粒度=是否跨分支：改了金额但仍在中额档（8000→9000）→ 不算跨档，仍回退回节点（避免小改动被强制重走的打扰）。
  • A7 动作 Tab 的重复配置项已删除，改为指向发起节点的说明文字——单一真源。

导入触发型流程的差异化（补 D-4）

基础信息选「导入触发」后，四步向导各步的语义切换。CardFlow 12 个导入流程是主力场景。

向导步骤人工发起型（已画）导入触发型（差异）
① 基础信息触发方式=人工发起+导入源配置：文件模板（Excel 列映射）/ 暂存表（STG）选择、触达方式（手动上传/定时拉取）、批次去重键（≥3 字段，对应既有跨批次去重机制）
② 卡片设计控件库拖拽（人填）语义转为「数据结构」：字段从导入列映射自动生成（只读来源标记 导入列 C），仍可增补人工字段（如"处理备注"）；无"必填"概念、代之以「缺值行为」：跳过行/默认值/进异常池
③ 流程设计发起人节点起点起点节点=「导入源」（图标▣ 灰紫色）：点开配置批次策略——按行建卡/按批次建卡（汇总卡+明细行）；分支条件可引用批次级变量（行数、合计金额、错误率）；人工节点通常只剩"异常处理"与"财务确认"两类
④ 发布设置去重/撤回/超时撤回不适用（隐藏）；+批次失败策略：整批回滚/跳过错误行继续（错误行进异常池生成待办）——对应既有批次恢复机制的语义（执行记录状态 10-14）
干跑预览手填样例值样例来源固定为「粘贴样例行 / 上传样例文件前 10 行」；路径推演按行分别展示（第 1 行→质检通过→凭证；第 3 行→质检阻断→异常池）；批次级条件用行集合计

设计裁决

  • 同一设计器双模，不做两个设计器：差异集中在起点节点与字段来源语义，四步骨架/抽屉/矩阵/诊断全部复用；模式在基础信息锁定后步骤 2/3 按模式渲染（切换触发确认：已配置的发起范围/导入映射将失效）。
  • 「缺值行为」替代「必填」是导入型的关键心智：没有人能被"要求填写"，只能定义系统如何处置缺值。
  • 定时触发型=导入型的子集（触达方式=定时拉取），不单列第三模式。

模板/复制落地的引用重绑检查（补 D-5）

创建副本后立即跑引用扫描，悬空项集中修复——类似 IDE 的 import 修复流。

副本已创建 · 需要重新绑定 4 处引用
从「费用报销单」复制到组织「宁晋公司」——以下配置在目标环境不存在或不可见
悬空节点「财务总监会签」处理人：王芳（不在宁晋公司可见范围）选择处理人 ▾
悬空自动凭证规则组：差旅报销规则组（属主体账套）选择规则组 ▾

保留动态引用（发起人部门主管 / 表单字段）无需重绑——解析时才取值
未处理的悬空项转为错误级诊断（不阻塞进入编辑器，阻塞发布）

规则

  • 扫描范围：静态成员引用（处理人/抄送/兜底/通知对象）、凭证规则组、账套、暂存表、群 bot——所有跨环境实体。动态引用（部门主管/角色/字段）天然可迁移，标绿说明。
  • 同名自动映射标黄需人工确认——"财务部"同名不同义是复制场景高频错。
  • 同组织复制跳过此弹窗（引用全部有效）；导出为模板时反向剥离静态引用为占位符。

E7 接管协议时序（消除竞态）
T0 李强点
「申请接管」
服务端登记全局唯一接管请求（第二人再点看到「王芳已有接管请求处理中，稍后重试」，无排队队列——排队制造更多竞态）
T0+0s
王芳端弹窗（应用内+钉钉）：「李强请求接管编辑」[允许] [拒绝，我在编辑]；同时其编辑器立即触发一次强制 flush（清防抖，未保存态落草稿）——从此刻起丢失窗口=0
王芳允许
或 60s 超时
移交执行：王芳界面瞬时转只读+横幅「已移交给李强 · 你的修改已保存至草稿」；李强端加载最新草稿进入编辑（含王芳最后 flush 的内容）；李强撤销栈从零开始（见 C6 修订）
王芳拒绝
李强收到 toast「王芳拒绝了接管请求」；30 分钟内不可再次向同一人发起（防骚扰）
异常
移交执行中王芳恰好断线 → 服务端以「已 flush 的草稿」为准直接移交（心跳超时兜底路径相同）；任何路径下草稿都只有唯一写者

协议不变量

  • 唯一写者不变量：任意时刻至多一人持写锁；移交=「flush→锁转移→旧端只读」原子序列，任何分支都不产生双写窗口。
  • 强制 flush 在弹窗时而非同意时：60s 超时移交路径下对方可能已离开电脑，等"同意时"再 flush 就晚了。
  • 命中率 0%/100% 标红是把「统计功能」反转为「纠错功能」的关键一笔——极值即异味。
