## 目录内容

- `rules/` — 44 条规则的完整 `F规则配置JSON`(文件名 `rule-{FID}-{类型}-{名称}.json`),外加 `FID 21` 的 `*.v1backup.json`(V1→V2 迁移备份)。
- `rules-manifest.json` — 44 条元数据:`fid/type/name/org/status/bytes/created/updated/edited/reproducibility(seeded|DB-ONLY)/file/note`。
- `wiring.json` — 59 个引用了规则的流程节点:`nodeId/flowVersionId/stageKey/stageName/pluginRegistryId/ruleId`。据此可知每条规则挂在哪个流程版本的哪个节点上(迁移后需照此重建接线,或直接连同流程/版本/节点一起搬)。

## 迁移时怎么用

规则的正确迁移方式是**按数据搬**(而非重跑种子):

1. schema、财务科目/账套(700xxx)、STG 表、组织192 等**由种子在目标库建**(它们没漂移);
2. 把 `rules/` 里的规则体**按原 FID `INSERT`** 回目标库 `CF自动插件_规则`(`SET IDENTITY_INSERT ON`,保 FID 不变);
3. 按 `wiring.json` 重建 `CF流程节点.F插件规则ID` 接线(或连同对应 `CF流程/CF流程版本/CF流程节点` 一起从 DEV 库搬);
4. 迁移后跑一次真实文件 E2E,验证凭证借贷平衡、导入落 STG 正确。

> 注意:凭证规则体内引用账套2的科目 FID 与网点辅助核算 FID——目标库这些 FID 必须对齐,否则凭证指向悬空科目。这部分由财务/账套种子保证,迁移后需校验。
